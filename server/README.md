# Yalova Realty — Server (Telegram bot + GitHub sync)

Один Node-процесс: telegraf-бот, который при сохранении квартиры
- скачивает фото из Telegram и заливает их в публичный GitHub-репозиторий,
- пушит обновлённый `catalog.json` в корень того же репо.

Сайт читает `catalog.json` через jsDelivr CDN, фото — оттуда же напрямую. Получается, что после первого пуша сайту вообще не нужен живой сервер — каталог раздаётся CDN и работает с любого устройства/хостинга.

## Локальный запуск

```powershell
cd server
npm install
# Скопируйте .env.example → .env и заполните переменные
npm start
```

Обязательные переменные в `.env`:

```
BOT_TOKEN=...                    # от @BotFather
ADMIN_PASSWORD=...               # пароль входа в бот

# Без этих трёх синхронизации не будет — бот будет писать только в локальный catalog.json:
GITHUB_TOKEN=ghp_...             # Personal Access Token c правом записи Contents
GITHUB_OWNER=Husan1405
GITHUB_REPO=yalova-realty
GITHUB_BRANCH=main
```

### Как получить GitHub PAT

1. github.com → Settings → Developer settings → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Repository access: **Only select repositories** → `Husan1405/yalova-realty`.
3. Permissions → Repository permissions → **Contents: Read and write**.
4. Скопируйте токен, вставьте в `.env` как `GITHUB_TOKEN=...`.

Альтернатива — classic token со scope `repo`. Работает тоже.

## Что происходит при старте

1. Бот запускается в long-polling режиме.
2. Если в `.env` есть GitHub-конфиг — запускается одноразовая миграция: для каждой записи каталога, у которой фото лежат в виде `file_id` (старый формат), бот скачивает их из Telegram и заливает в `photos/` GitHub-репо, подменяя `file_id` на постоянный CDN-URL. Затем пушит обновлённый `catalog.json` в корень репо.
3. В дальнейшем все добавления/правки квартир и фото автоматически пушатся в репо. После пуша вызывается `purge.jsdelivr.net` — обновления видны на сайте через секунды.

## Сценарии в боте

1. `/start` → введите пароль администратора.
2. Главное меню: ➕ Добавить · 📋 Список · 🗑 Удалить · ✏️ Редактировать · 🚪 Выйти.
3. **Импорт из канала:** форварднь пост (с фото + подписью) администратору в этот бот. Бот соберёт media-group, распарсит подпись по шаблону `Key: Value`, спросит недостающие обязательные поля и покажет превью.

### Формат подписи в канале

Обязательные: `Тип`, `Заголовок`, `Цена`, `Статус`. Остальное — опционально.

```
Тип: квартира
Заголовок: 2+1 в центре Ялова
Цена: 85000 USD
Статус: продажа
Площадь: 95
Комнаты: 2+1

Описание идёт после пустой строки.
```

Допустимые значения:
- `Тип`: `квартира` | `вилла` | `участок`
- `Статус`: `продажа` | `аренда`

`/cancel` — прерывает текущее действие.

## Как сайт читает каталог

`index.html`:
```html
<script>
  window.CATALOG_URL = 'https://cdn.jsdelivr.net/gh/Husan1405/yalova-realty@main/catalog.json';
</script>
```

`script.js` подмешивает к URL `?t=<timestamp>` чтобы браузер не кэшировал, и опрашивает каталог каждые 60с. Фото в `photos[]` хранятся как готовые URL (`https://cdn.jsdelivr.net/gh/.../photos/<file>.jpg`) — фронт использует их без преобразования.

Сервер-бот для сайта при работе с GitHub-хранилищем **больше не нужен онлайн** — он только обновляет данные. Сайт работает на чистом CDN.

## Поля квартиры

| Поле        | В catalog.json (raw) | После `normalize()` на фронте |
|-------------|----------------------|-------------------------------|
| `type`      | `квартира/вилла/...` | `apartment/villa/land`        |
| `status`    | `продажа/аренда`     | `sale/rent`                   |
| `photos`    | `[url, url, ...]`    | `[url, url, ...]`             |

## Если хочется работать без GitHub (legacy)

Не указывайте `GITHUB_*` в `.env`. Тогда бот ведёт себя как раньше: каталог только в `server/catalog.json`, фото проксируются через `/api/photo/:fileId`. В `index.html` задайте `window.BOT_API_HOST = 'http://адрес-бота'`. Минусы — сайт привязан к доступности бота, не работает с других машин.

## Ограничения

- **GitHub API лимит:** 5000 запросов/час с PAT — это ~5000 операций бота. Для редкого добавления квартир — с огромным запасом.
- **jsDelivr CDN кэш:** ~12 часов без purge, но бот после каждого пуша делает purge — обновление через секунды. Если purge упадёт, изменения подтянутся в течение нескольких минут.
- **Размер фото:** GitHub Contents API ограничивает один файл 100 MB; Telegram даёт фото до ~10 MB. Хватит с запасом.
- **Один админ.** Пароль один на всех; защита от перебора — 3 попытки → блок на 60с.
